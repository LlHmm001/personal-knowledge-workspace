## 产品目标与本轮取舍

PKW 已具备“保存资料 → 整理笔记 → 查找知识 → 创建待办 → 删除与恢复”的主要入口。本轮首要目标是让这条日常使用链路安全、可信、可恢复：写下的内容不能因切换页面丢失；删除旧资料不能误伤同位置的新资料；保存、解析、检索和升级的状态必须说明真实发生了什么。

用户已授权开发、产品项目、设计交互三个团队全面升级，并进一步确认：各项日常体验都需要；支持个人和多人使用；采用“每人有私人空间，另建团队共享空间”。本轮因此覆盖九条核心旅程，并形成角色、权限、空间隔离和迁移设计。资料规模、首批团队规模、真实检索样例和部署入口仍待了解；它们只影响相应的评测/生产步骤，不阻断当前修复。新增 AI 工作流、整个视觉系统替换与性能预算仍须有真实样例和基线。

“本地优先”在这里指 Markdown、附件及任务的本地服务不依赖 WeKnora 可用性。它**不等于**浏览器与 PKW 服务器断网后仍可创建和保存；目前 UI 通过 `/pkw/api` 请求宿主，没有证据支持离线浏览器应用的承诺。

## 冻结边界复核

- Markdown Note、Attachment 二进制和 Task Store 各自是其领域的 canonical；不新增第二套权威数据。
- NoteId 与 AttachmentId 保持稳定，路径和文件名只表示位置与展示。Folder 仍是目录派生，无 Folder entity。
- WeKnora 只负责解析、索引、检索和派生内容。Main/Processing → Business 的 A2 聚合与 active canonical 过滤保留，本地读取和保存不依赖其可用性。
- 浏览器通过宿主 RPC 使用能力，不直接调用 fs、SQLite 或 WeKnora；内部 remote ID 不作为业务身份。
- 手机继续 read-first；无新编辑器/真机证据时，不开放正文编辑。
- 不自动重开 DOCX canonical、绝对路径身份、resource 集成或把附件全文物化到 Main Knowledge 等已拒绝方向。
- 数据损坏、身份误伤属于冻结决策允许修复的问题；修复危险行为不需要顺带重构 Foundation。

### 服务端与冲突恢复的最后复核

独立只读复核又发现并关闭了两项本轮变更新引入的阻断点：

- `syncSnapshot` 从只保留活动操作改为保留最新操作后，附件列表、附件详情、Knowledge 列表仍以“存在 intent”判断 pending，导致 completed 也永久显示等待。现在这三处与 `syncView` 统一调用 `activeSyncIntent`，仅 pending/running/unknown/retryable 视为活动；permanent 可显示错误但不冒充仍在运行，completed 清除历史错误。协调者报告对应 Web 集成测试通过，最终全量验证另行记录。
- 冲突“重新读取”原先先销毁编辑器再请求最新版本，网络失败会丢失唯一草稿。独立执行实际函数曾确认原稿变为空、页面只剩错误提示。修正为先读取成功，再替换编辑器；失败保留原稿和复制入口，读取期间又有新输入则取消替换。独立实际函数复验“读取失败保稿”和“读取期间继续输入保稿”两项均通过。

CAS 接口代码复核未发现新的哈希不一致：`getNote` 从实际返回的 Markdown 计算 SHA-256，CRLF → LF 归一化规则与 Notes 服务一致；`saveNoteBody` 读取 frontmatter 后将同一快照的版本与原文哈希带入更新，Notes 在串行写入锁内校验当前文件，成功后返回新版本/哈希供后续保存使用。错误码通过 HTTP 409 到达 UI；冲突时暂停自动重试、保留 dirty，复制失败提供手动选择入口。上述结论限定于代码与受控状态复验，双窗口真实浏览器和最终安装包验证仍由协调者完成。

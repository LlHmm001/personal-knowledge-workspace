# 私人空间与团队空间：部署及运维交接

本方案对应约 15 人使用、每人独立私人空间、另建团队共享空间。旧资料全部归原所有者私人空间，由本人预览后主动复制到团队。生产地址由用户确认是 `https://ddmind.duckdns.org/pkw`；服务器运行方式、真实文件路径、存储版本、宿主版本和现有 UI 补丁仍需清点。以下是可复现的部署流程和占位示例，不是已经执行过的生产命令。

## 两种入口与发布边界

推荐运行独立的 `serve-collaboration.mjs`，只监听 `127.0.0.1:3081`，对外反向代理整个 `/pkw` 路径。它使用已安装的 PKW tarball 和宿主依赖，但不暴露其他 Harness 页面或通用 RPC。每个空间懒加载独立的 SQLite、文件目录和服务上下文。

另一种方式是宿主加载 `@deepseek-ai/dsh-pkw-web/lib/collaboration/index.js` 导出的服务。此时必须移除原 `pkwWeb` 路由插件并审查宿主其他端点。新插件注册失败不会自动关闭旧插件；不得把“新插件拒绝重复路由”误认为旧无鉴权入口已关闭。

旧 `deploy-pkw.mjs` 负责已有 profile 的包升级、UI 补丁审查及包级回退，**不自动启用协作、不迁移数据、不修改反向代理**。先按 [BUILD_AND_DEPLOY](../BUILD_AND_DEPLOY.md) 安装并验证实际包，再单独走本页流程。

## 配置与首次初始化

部署者先确定非公开的数据目录，目录 0700、文件 0600；配置只包含环境变量名字，不写密码或 API key。示例 `collaboration.json`：

```json
{
  "dataPath": "/absolute/new/collaboration-root",
  "publicOrigin": "https://ddmind.duckdns.org",
  "bootstrapUsername": "replace_with_owner_account",
  "bootstrapPasswordEnv": "PKW_BOOTSTRAP_PASSWORD"
}
```

`publicOrigin` 不带 `/pkw` 或末尾斜线，必须与浏览器实际 HTTPS origin 一致；Host 和 Origin 均在服务端校验。首次密码通过服务管理器的受保护环境配置提供，至少 15 个字符。不要放进 Git、命令参数或对话。首次启动只创建所有者及私人空间；以后启动不会从 bootstrap 配置重置密码，可以移除 bootstrap 环境秘密。

```sh
node scripts/serve-collaboration.mjs \
  --profile /absolute/installed-profile \
  --config /absolute/private-config/collaboration.json \
  --port 3081
```

必须先在隔离测试入口初始化并登录，取得自己的私人空间 ID；**导入旧资料前不要点开该空间**，因为首次进入会创建空工作区，导入器将安全拒绝覆盖。停掉新入口，再执行旧资料导入。服务始终单实例；`gateway.lock` 被占用或恢复审核未完成时拒绝启动。进程崩溃留下锁时，先确认进程和其他写入者均已停止，再按实际故障处理锁，不能定时删除或自动抢锁。

## 旧资料保全、归属与切换

完整参数和退出码见 [DATA_MIGRATION](DATA_MIGRATION.md)。顺序必须保持：

1. 只读清点旧系统运行版本、全部 workspace/state、远程知识库和手改 UI。网页计数仅是抽样，不是数据备份清单。
2. 停止旧系统所有写入者，包括同步任务、其他应用和直接文件编辑。创建全新备份，保存清单 SHA-256 到备份目录之外。
3. 校验备份并检查域版本、稳定 ID、引用、回收站及 SQLite 完整性。未知 JSON/schema 先保全，针对实际格式开发转换器；不改版本号冒充迁移。
4. 用 `adopt-private-space.mjs` 将副本绑定刚初始化的本人私人空间。要求所有者账号、私人空间 ID、备份清单哈希和停写确认；不允许团队目标、不覆盖已有空间。只在副本调整 workspace 注册路径，保留原 workspaceId 和业务 ID。
5. 在隔离入口打开导入后的副本，核对原正文/附件字节、笔记/任务/矩阵/事件/回收站/映射、修改保存、重启后读取及只读成员无法访问旧私人内容。对真实数据完成核验后才能算生产迁移通过。
6. 正式切换前，在源仍保持停写时执行 `verify-source`。发现备份后新增或修改就重新备份和演练，不能带着旧快照切换。
7. 反向代理将 `/pkw` 和 `/pkw/…` 全部指向新入口；检查旧监听端口和其他域名不能绕过鉴权。最后才允许用户登录和新写入。

如果采用 Nginx，等价路由结构如下；证书、站点其他路由、上传限制、容器网络和真实 upstream 需按服务器配置合并审查：

```nginx
location = /pkw {
    proxy_set_header Host $http_host;
    proxy_pass http://127.0.0.1:3081;
}
location ^~ /pkw/ {
    client_max_body_size 32m;
    proxy_set_header Host $http_host;
    proxy_pass http://127.0.0.1:3081;
}
```

`proxy_pass` 无路径后缀，以保留原请求路径。不要另留指向旧服务的 `/pkw/api`、附件、编辑器资源或空间路径。健康端点 `/healthz` 只证明进程可响应；不能替代迁移、鉴权和数据验收。

## 账号、成员和主动分享

登录页默认不勾选“在此设备保持登录 30 天”：普通登录有效期为 12 小时，勾选后为 30 天，均从登录成功起计算，不因后台请求无限续期。已取消 30 分钟无请求即失效的限制。共享或公共设备不应勾选；退出、改密码和离线账号恢复仍立即撤销相应会话。服务器正常重启保留有效登录。

空间页面登录过期时回到登录入口，重新登录且仍有空间权限才返回原空间。接口继续返回 401，编辑中的页面保留草稿并要求用户手动重新验证及保存，不自动刷新或重放写请求。登录修复的兼容升级说明见 [SESSION_LOGIN_FIX](SESSION_LOGIN_FIX.md)。已经在使用协作空间的服务器升级此修复时，保留现有身份库和空间根；**不要重做首次初始化或从旧快照重新导入资料**。

公开自助注册关闭。所有者/管理员在团队里生成一次性、24 小时有效且绑定角色的邀请；新用户使用邀请创建账号，同时获得自己的私人空间。已有账号先登录再接受邀请。邀请被使用、撤销或创建者失去相应权限后不能继续授予成员资格。

团队所有者管理所有角色和所有权转移；管理员管理编辑者/阅读者，不能变更所有者或授予管理员；编辑者可编辑和移入回收站，不能永久清除；阅读者可查看、搜索和下载。私人空间不提供成员邀请。团队角色不赋予他人私人资料权限。当前没有组织目录、SSO、MFA、逐笔记 ACL、团队删除或企业审计导出，不把它们当作已交付能力。

分享采取“私人原稿 → 团队副本”：先展示正文、附件及提示，再明确确认。原稿不变，副本使用新 NoteId/AttachmentId；不会自动递归分享其他链接笔记、任务或历史。确认前原文或附件发生变化需重新预览。重复确认复用同一回执；进程异常导致结果不确定时显示待核查，不盲目重试复制。

这是应用层空间隔离，不是端到端加密。能读取服务器磁盘/备份的系统运维人员仍能读取其中资料。整套备份必须按包含全部成员私人内容的敏感文件保存，不上传到公开位置。

## 搜索配置与验收

未配置或远端不可用时，本地关键词检索仍可查当前空间笔记正文和附件文件名，界面明确显示范围。它不提供附件内部语义全文。每个空间只能绑定自己的专用远端知识库，不得把旧私人 KB 同时给团队或其他账号使用。

可在配置中追加以下结构，空间 ID、地址和 KB ID 必须由真实环境取得：

```json
{
  "retrieval": {
    "sp_REPLACE_WITH_32_LOWERCASE_HEX": {
      "baseUrl": "https://replace-with-search-service.example",
      "kbId": "replace-with-dedicated-kb-id",
      "apiKeyEnv": "PKW_OWNER_WEKNORA_API_KEY"
    }
  }
}
```

这是结构说明，示例 ID 故意不是合法运行值。原有 KB、同步映射和解析配置应按实际迁移清单保留及复验。检索工具和真实查询集验收见 [RETRIEVAL_ACCEPTANCE](RETRIEVAL_ACCEPTANCE.md)；本地降级命中不能替代远端检索质量验收。

## 备份、恢复与账号找回

启用协作后备份范围变为整个协作根目录：身份、成员、全部空间、附件、事件及分享回执。使用 [DATA_MIGRATION](DATA_MIGRATION.md) 的整套冷备流程；必须停写、校验、恢复到全新目录。恢复会撤销旧会话/未使用邀请并留下 `recovery-pending.json`，审核成员后显式解除门禁才可启动。恢复旧备份可能重现曾被移除的成员，因此审核不能省略。

忘记密码由能管理服务器的部署者在停服后执行离线找回，不开放匿名重置接口：

```sh
node scripts/recover-account.mjs \
  --profile /absolute/installed-profile \
  --data-root /absolute/real/collaboration-root \
  --username existing_account \
  --password-env PKW_RECOVERY_PASSWORD \
  --offline-confirmed
```

新密码事先通过受保护的环境变量提供；命令不输出密码，撤销该账号全部会话并记审计，内容和成员关系不变。随后移除临时环境秘密并启动服务。先做冷备，且不要在正常运行时直接改 SQLite。

上线后若需要回退，先停新系统写入并备份新资料，分析差异，再确定数据回退方案。不能用旧库覆盖已经接收新写入的库；回退 node_modules 不等于回退资料。单实例运行与本机合成场景测试不构成目标服务器的 15 人容量承诺，还需在真实服务器记录并发读取、保存、搜索、内存和响应时间。

## 生产完成标准

生产交付回执需要同时具备：确切提交与安装包哈希、宿主/域版本、旧源和新目标对账、所有资料归本人私人空间的验证、匿名及跨空间访问拒绝、角色变化立即生效、真实检索和解析验证、重启与备份恢复演练、反向代理/旧入口关闭证据，以及约 15 人负载的目标侧数据。没有这些证据时只标注本机或源码通过，不宣称已完成生产升级。

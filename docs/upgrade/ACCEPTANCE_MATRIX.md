## 可执行验收步骤

使用隔离测试工作区，准备两篇笔记 A/B、一份含表格/脚注的笔记、中文命名 TXT/PDF/图片与 HTML/SVG 样本、两个任务矩阵及父子任务。所有内容为合成样本；对比正文、ID、路径、状态和原文件字节，不只看成功提示。

### J1：第一次打开

1. 不配置 WeKnora，创建、读取、修改笔记；页面应说明等待配置，本地资料仍可用。
2. 配置凭据 provider 分别立即拒绝、永不返回；状态诊断应有上限（本轮300ms），本地读取不能无限等待。恢复 provider 后下一次查询应能显示已配置。
3. 有有效本地配置但远端服务停止：不能由“已配置”推断“已连接”；保存成功与索引完成分开显示。
4. 当前空白页应提供写笔记、上传或去相关入口的可理解引导；未逐页走查的部分保持未验证。

### J2：编辑全过程

1. 触发慢保存 A，继续输入 B，再切 Home、侧栏另一Note、知识页、Wiki目标及编辑模式；最终重新读取包含应保存的内容，失败保留当前编辑器。
2. 表格增删行列、脚注编辑/删除发出后继续输入，或切至另一笔记；旧转换结果应被拒绝并提示重试，不得覆盖新内容。未改变的草稿仍可正常应用操作，包括删除最后表格得到空正文。
3. 附件上传等待期间切换笔记，上传仍归原笔记，回调不向新笔记插入链接。
4. 手机仍不开放正文写入。关闭浏览器前的提示不是草稿持久化副本；本轮没有新增浏览器离线草稿存储。

### J3：冲突恢复

1. 两窗口读同一版本；A保存成功后B保存必须返回HTTP409，A内容保持，B草稿可复制。
2. B修改草稿后自动重试应暂停；不能等待一阵后强制覆盖A。复制API失败时应提供手动复制入口。
3. 取消重新读取保留草稿；确认后请求失败仍保留草稿和恢复控件；等待读取期间输入新内容，应取消替换。
4. 成功读取最新版后再修改和保存，应使用新版本/原文哈希。浏览器完成度和服务测试分别记录。

### J4：整理目录

1. 分别从桌面文件夹工具栏“⋯”、右键和手机菜单重命名测试文件夹，再移入回收站；目标路径必须一致。
2. A移动到B占用的位置、恢复到占用位置，均明确失败且A/B各自可找回；同Note移动后NoteId不变。
3. 创建/重命名文件夹的请求未返回时继续输入；离开编辑器前保护这段输入，取消操作不得取消已有读取。
4. 批量移动/删除遇到一个冲突时，核实每项结果和选中范围，不用一个总成功提示掩盖失败。

### J5：附件全过程

1. 上传中文命名文件，确认字节大小、原文件下载、Note引用/owner和Companion关系；重复打开不新建另一份身份。
2. 快速选择A/B且让A后返回，页面详情、预览、下载、删除操作必须全部属于B；旧请求错误不干扰新选择。
3. HTML/SVG/XHTML普通路径及preview路径保持下载，响应含nosniff/no-store和受限CSP；中文下载名称合法，字节不变。常用图片/PDF和TXT预览仍可用。
4. 远端解析失败或停滞不能假称完成；真实解析、OCR、摘要需真实服务样本验证，本轮mock不替代。

### J6：找资料

1. 查询A后立即查询B，交错两者成功/失败，最终只显示B；清空并返回主页后旧请求不恢复结果。
2. 失败A后输入B再点重试，应实际搜索B；按Enter与触屏按钮行为一致。
3. 远程主查询不可用或未配置时，只在当前空间做本地关键词，持续显示“笔记正文/附件文件名，不含附件内部全文/语义”提示；不要把降级后空结果解释为所有来源都无答案。PKW 自身不可达仍应显示请求失败。
4. 远程模式 `trace.processingUnavailable=true` 时保留附件部分检索不可用提示，即使有结果也不可隐藏；已删除canonical即使远端未清理也不出现在业务结果。换用户/空间后迟到请求不能回填旧内容。
5. 真实评测含标题、罕见词、语义、附件内部句子及无答案；记录业务ID/预期、模式与partial比例、漏召/误召、时延和版本。合成结果不冒充质量改善；详见 RETRIEVAL_ACCEPTANCE。

### J7：资料到行动

1. 从Note和选区建任务，完成、重开、移动矩阵；TaskId/sourceRefs/重要紧急属性保持。
2. 不存在matrix、已删/不存在parent、自指矩阵重分配及父子循环请求全部拒绝，拒绝前后记录不变；RPC显式matrixId:null只返回Inbox，省略才返回全部。
3. 删除矩阵选择迁移时任务进Inbox；选择一起删除时只软删成员，其他矩阵的活动子任务提升顶层。已软删任务的矩阵引用也处理。
4. 恢复时原矩阵缺失/归档则回Inbox；父任务失效或不可达则提升顶层，仍保留来源与属性。尤其覆盖“父子原属归档矩阵，恢复子任务”并检查实际列表可见。
5. 慢保存期间修改标题/说明，旧响应不能清除新dirty；保存并关闭遇到新输入必须留在表单。清空截止/计划日期后重新读取确已移除。
6. `listTrashTasks` RPC只列deleted任务，回收站资料区域下方已有独立“已删除任务”列表与逐项恢复。实际脚本专项已过；最终浏览器仍要验删后可见、恢复后离开回收列表且重新可找到、viewer不能恢复、失败留在列表且可重试。Task不加入资料checkbox/全选/清空/永久删除；旧清空明确为“清空已删除资料”。

### J8：找回和清理

1. 删除旧A→在同路径新建不同ID的B→永久清除A，B正文/文件/索引/ID均不变。
2. 文件夹同名复用后恢复/清除旧归档，按归档实际成员身份处理，不误伤新文件夹。
3. 注入归档移动/索引写入失败，至少留下一份可恢复资产和可解释状态；不能用空回收站假称已完成。
4. 混合Note/Attachment/Folder批量操作记录每项成功、失败原因；冲突项维持原资产，正常项不重复处理。

### J9：手机与键盘

1. 390px下从笔记到附件、知识搜索、任务完成/重开、更多菜单和回收站，页面无内容溢出、按钮可触发。
2. 桌面只用Tab/Enter/Space打开笔记、目录、知识结果和任务，多选框重绘后焦点仍可使用；图标按钮有可理解名称。
3. 用用户主要手机型号/浏览器实际验PDF/图片预览、返回、软键盘搜索；记录设备和版本。未取得真机证据保持“待验”，不以浏览器改宽度代替。
4. 统一dialog已有实现；仍需逐个验上传、任务详情、嵌套关闭确认、手机sheet的Tab循环、Esc、关闭焦点恢复与背景inert。屏幕阅读器、手机真机和编辑器IME不自动继承这些自动化结果。

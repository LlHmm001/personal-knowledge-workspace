### 保存反馈从“请求完成”变为“这份内容已经保存”

原 `autosave()` 在请求结束后无条件 `dirty=false`。使用基线实际页面函数、延迟保存响应可稳定复现：请求提交 `snapshot A`，输入框随后变为 `newer snapshot B`，返回后 persisted=A、draft=B、dirty=false。这会产生错误的“已保存”提示，并使导航丢弃 B。

现在一次保存绑定原始 NoteId、editor 对象和内容快照。同一编辑器的保存按顺序执行；响应只确认本次提交的内容。输入仍变化时保留未保存状态并补存。用户导航等待最新内容落盘，失败保留原编辑器。页面离开警告也覆盖仍在保存中的状态。

新建/重命名目录的服务器请求期间仍可能输入，所以响应后也检查导航归属并保存新增内容。取消“新建”对话框不会使当前笔记加载悬空。重复点击当前“笔记”或“知识”入口不会取消正在进行的加载。

### 多处编辑有明确恢复入口

浏览器把 `getNote` 返回的 revision 和 content hash 随保存送回 Host，并接受保存返回的新令牌。服务器返回 `PKW_NOTE_CONFLICT` 时：

- 保留编辑器内容和未保存状态，暂停自动重试，防止旧内容反复提交；
- 显示中文/英文解释，告知当前草稿仍在、服务器没有被覆盖；
- 提供“复制草稿”，剪贴板不可用时展开文本框供手动复制；
- “重新读取”必须先确认会丢弃当前未保存稿，先成功取得服务器最新内容，再替换编辑器；读取失败继续保留草稿和复制入口，读取期间继续输入则取消替换。

这一体验依赖同批 Host/Notes 条件更新实现，不能单独把 UI 检查当成并发写入保护。服务器宕机、浏览器崩溃或用户明确关闭窗口时，内存草稿没有新增持久化副本；没有引入第二套 canonical 或无审计的本地草稿库。

### 搜索讲清“找到什么”和“下一步做什么”

原页面只支持 Enter，首次开始检索后没有返回主页按钮；旧查询成功/失败及较晚的主页加载可能覆盖新查询。现在搜索通过表单提交，始终有明确的提交动作；检索显示当前词、结果数量、加载状态、错误说明及重试。返回主页会取消旧结果的 UI 所有权。

把未被证据支持的“正文命中 / 附件命中”改成“笔记内容检索 / 附件内容检索”，附简短的相关性核对提示。没有把文案修改冒充 reranker：检索质量闸门仍需独立设计、实现和真实查询集验收。

错误提示不承诺浏览器断网后还能通过 RPC 编辑；改为说明检索失败不改变已经保存的内容，并提供检查连接和回到笔记的方向。技术错误保留在可展开详情中。

### 信息诚实与可访问性

`renderPage(version)` 使用安全 JSON 编码显示实际安装包版本，替代固定旧 SHA；正文详情不再显示远端 knowledgeId。搜索输入有程序化标签，搜索/保存/上传状态具备 live region，当前导航有 `aria-current`，键盘焦点可见，减少动态效果偏好下停止加载旋转。

首轮真实浏览器检查发现 Vditor 3.11.3 工具栏有一个名称为 `undefined` 的按钮。源码把不受该版本内置支持的 `mark` 作为内置工具；已改为带明确名称、图标和动作的自定义高亮工具。没有修改 Vditor 依赖或把手机编辑重新开放。

## 第二轮：异步编辑安全与可操作入口

第二轮继续审查时，产品团队用真实 `renderPage()` 脚本和可控延迟响应复现了新的阻断问题：表格/脚注转换可能把 A 的正文写进 B；任务保存 A 后会把等待期间新增的 B 错标为已保存；同视图附件 A 的晚响应可能覆盖 B 的详情及删除按钮。以上不是仅凭字符串判断，已纳入本轮修复和回归。

| 验收场景 | 变化 | 开发机结果 | 限制 |
| --- | --- | --- | --- |

### 真实浏览器发现的新增回归与修正

主协调者随后在真实浏览器发现：桌面任务标题点击会完成/重开任务。根因是本轮移动端按钮替换范围过宽，将桌面 `taskRow` 的 `<span data-action="toggle-task">` 结束标签错误改成 `</button>`；浏览器修复异常 HTML 后改变了动作祖先关系。已作单处闭合标签修正。

新增五项回归先复现桌面两种状态失败，修正后 **5 passed**（其他 84 项本次未重跑）：桌面/移动 × 未完成/已完成的标题实际委托只打开详情、状态控件只完成/重开；另外对本轮十类导航片段严格检查标签平衡与禁止嵌套按钮。总 UI 用例数现在为 89，但完整 89 项的最终运行结果以主协调者验证为准。该片段检查不是浏览器渲染器替代品，真实浏览器确实提供了先前测试没有覆盖的证据。

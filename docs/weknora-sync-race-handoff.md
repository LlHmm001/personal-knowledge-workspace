## 先保护已有工作与旧数据

- **保留 DSH 隔离 checkout 中的 JSON→SQLite 转换器及两处测试文件补丁。** 由服务器执行者确认实际文件路径，保存基础版本、完整差异、未跟踪文件和文件哈希，形成可恢复补丁副本。更新隔离 checkout 前核对这些内容；不得用 reset、clean 或整体覆盖把它们丢掉。后续合并冲突逐项解决，重新验证转换器和保留的测试，不假定两处测试补丁属于转换器，不得以删除补丁换取通过。
- 旧正文、附件、任务/矩阵、事件、回收站、稳定业务 ID、同步队列及映射均纳入保全和对账；配置、现有定制补丁及根目录外的凭据配置也要单独清点和受控备份。凭据不得写入 Git、公开报告或资料正文。
- **旧资料全部归确认后的原所有者（owner）私人空间**，不自动进入团队共享空间。保留原始数据副本；转换只在隔离副本中进行，不直接改版本号冒充迁移，不覆盖既有目标。配置按原用途恢复，不能因为迁入私人空间而丢失或公开密钥。

发布候选必须绑定**新的精确 commit SHA**和实际安装包哈希，同时记录 DSH 基础版本及保留补丁的哈希、Node/pnpm 环境。服务器全门禁必须测试这一组合；若随后变更代码、转换器或安装产物，相关证据重新生成，不能沿用旧候选的放行结论。真实 WeKnora 等外部验收缺失或跳过时，继续明确标为未验证。

## 真实数据演练与切换顺序

1. 按 [数据迁移与恢复说明](upgrade/DATA_MIGRATION.md) 清点全部源路径及写入者。停止所有写入后制作冷备，将独立清单哈希保存在备份之外；原源和原始副本均保留。
2. 在全新隔离目录运行已保留的显式转换器，核对转换前后稳定 ID、正文/附件、结构化记录、引用及历史。再导入确认后的 owner 私人空间，实际验证读取、修改保存、重启、同步收敛和跨空间拒绝；不能只看 HTTP 健康或文件数量。
3. 完成备份→全新目录恢复→实际运行验收。协作整根恢复还必须验证旧会话/邀请失效，复核恢复时点的成员权限，并按工具流程解除恢复门禁；不得删除门禁文件绕过审核。部署环境变量及根外配置另行验证已恢复。
4. 用户已授权完整交付；DSH 按新 SHA 完成服务器全门禁、真实数据隔离演练及备份恢复并通过后，继续按 [协作部署说明](upgrade/COLLABORATION_DEPLOYMENT.md) 和 [构建部署说明](BUILD_AND_DEPLOY.md) 执行既定部署，无需新增根团队人工审批。正式切换前，在源持续停写时再次执行 `verify-source`；有漂移就重新备份、演练和核验。异常时停止受影响操作并报告，保留现场和回执；不得绕过失败门禁继续切换。保留旧入口关闭、匿名及跨空间访问拒绝的证据。
5. 上线后如需回退，先保护新增写入和最新权限变化，再执行经过验证的回退方案；不得直接覆盖旧快照，也不得恢复未鉴权的旧入口。

本补充说明不代表修复、服务器验收或部署已经完成。只有对应新候选的服务器全门禁、真实资料隔离演练及备份恢复证据齐备，才能关闭此次部署阻断；最终状态由根团队维护的交付记录登记。
